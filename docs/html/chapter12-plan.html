<h1>第十二章：计划与任务分解</h1> <p>在复杂任务的处理过程中，Agent 需要将一个笼统的目标分解为可执行的子任务，并按照计划逐步推进。AgentScope Java 提供了完整的 **计划系统（Plan System）**，通过 <code>PlanNotebook</code> 实现任务的分解、执行与状态追踪。本章将深入解析这一核心功能。</p> <h2>12.1 计划系统架构</h2> <h3>12.1.1 核心组件</h3> <p>AgentScope Java 的计划系统由以下几个核心组件构成：</p> <pre><code class="language-">┌─────────────────────────────────────────────────────────────────┐ │ PlanNotebook │ │ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ │ │ Plan │ │ SubTask[] │ │ PlanStorage │ │ │ │ (当前计划) │ │ (子任务列表) │ │ (存储后端) │ │ │ └─────────────┘ └─────────────┘ └─────────────┘ │ │ │ │ │ │ │ ▼ ▼ ▼ │ │ ┌─────────────────────────────────────────────────┐ │ │ │ PlanToHint (提示生成) │ │ │ └─────────────────────────────────────────────────┘ │ └─────────────────────────────────────────────────────────────────┘ </code></pre> <ul><li>**PlanNotebook**：计划笔记本，负责管理当前计划、子任务状态、存储和提示生成</li> <li>**Plan**：计划实体，包含名称、描述、子任务列表和执行状态</li> <li>**SubTask**：子任务实体，包含名称、描述、预期结果、实际结果和状态</li> <li>**PlanStorage**：计划存储接口，支持内存、数据库等多种存储后端</li> <li>**PlanToHint**：计划到提示的转换器，根据计划状态生成上下文引导</li> </ul> <h3>12.1.2 计划状态模型</h3> <pre><code class="language-">PlanState (计划状态): ├── TODO - 计划已创建，未开始执行 ├── IN_PROGRESS - 计划正在执行中 ├── DONE - 计划已完成 └── ABANDONED - 计划被放弃 <p>SubTaskState (子任务状态): ├── TODO - 子任务待执行 ├── IN_PROGRESS - 子任务执行中 ├── DONE - 子任务已完成 └── ABANDONED - 子任务被放弃 </code></pre></p> <h3>12.1.3 工具函数体系</h3> <p>PlanNotebook 提供了 10 个内置工具函数，Agent 可通过调用这些工具来管理计划：</p> <table border="1" cellpadding="8" <h3>12.2.1 任务分解原则</h3> <p>有效的任务分解应遵循以下原则：</p> <p>1. **原子性**：每个子任务应是一个不可分割的最小执行单元 2. **可验证性**：子任务应有明确的预期结果，便于验证完成状态 3. **顺序性**：子任务之间应存在逻辑上的先后依赖关系 4. **独立性**：子任务应尽量减少相互依赖，降低执行复杂度</p> <h3>12.2.2 创建计划的最佳实践</h3> <p>在创建计划时，应提供清晰的信息：</p> <pre><code class="language-java">// 创建计划的示例 String planName = &quot;构建电商网站&quot;; String description = &quot;使用 Spring Boot + Vue 子任务状态转换规则</h3> <p>系统对子任务状态转换有严格的约束：</p> <pre><code class="language-">TODO ──────► IN_PROGRESS ──────► DONE │ │ │ ▼ └──────────► ABANDONED </code></pre> <p>**状态转换约束**： <ul><li>只有当前子任务（index 最小的非完成子任务）才能标记为 <code>IN_PROGRESS</code></li> <li>标记子任务为完成时，系统会自动激活下一个待执行子任务</li> <li>只能将状态更新为 <code>TODO</code>、<code>IN_PROGRESS</code> 或 <code>ABANDONED</code>，<code>DONE</code> 状态必须通过 <code>finish_subtask</code> 设置</li> </ul> <h3>12.2.4 计划修订策略</h3></p> <p>在计划执行过程中，可能需要修订计划：</p> <pre><code class="language-java">// 添加子任务 planNotebook.reviseCurrentPlan(2, &quot;add&quot;, Map.of(&quot;name&quot;, &quot;新子任务&quot;, &quot;description&quot;, &quot;描述&quot;, &quot;expected_outcome&quot;, &quot;结果&quot;)); <p>// 修改子任务 planNotebook.reviseCurrentPlan(1, &quot;revise&quot;, &quot;delete&quot;, null); </code></pre></p> <h2>12.3 计划执行与监控</h2> <h3>12.3.1 执行流程</h3> <p>计划执行的标准流程如下：</p> <pre><code class="language-">1. 创建计划 (create_plan) │ ▼ 2. 用户确认后开始执行 │ ▼ 3. 标记第一个子任务为 IN_PROGRESS (update_subtask_state) │ ▼ 4. 执行子任务 → 调用工具完成实际操作 │ ▼ 5. 完成子任务 (finish_subtask) → 记录具体结果 │ ▼ 6. 系统自动激活下一个子任务 │ ▼ 7. 重复 4-6 直至所有子任务完成 │ ▼ 8. 完成计划 (finish_plan) → 总结整个过程 </code></pre>
