<h1>第八章：多代理架构模式</h1> <p>> 本章深入讲解 AgentScope Java 框架下的多代理协作模式，涵盖 7 种核心架构模式，并通过完整案例展示如何用 Java 21 + Spring Boot 3 构建复杂的多代理系统。</p> <p>---</p> <h2>8.1 多代理协作概述</h2> <h3>8.1.1 为什么需要多代理？</h3> <p>单代理（Single Agent）受限于其设计目标：每个 Agent 只有一套系统提示词、一组工具和有限的上下文窗口。当业务场景变得复杂时，单代理往往会出现"能力稀释"问题——试图让一个 Agent 兼顾所有职责，结果反而每件事都做不好。</p> <p>多代理架构通过将职责分离，让专业 Agent 做专业的事： <ul><li>**解耦复杂任务**：将问题分解为多个子问题，每个子问题由专门的 Agent 处理</li> <li>**提升模型效率**：不同 Agent 可以使用不同规模/成本的模型</li> <li>**增强可维护性**：每个 Agent 的职责单一，调试和优化更清晰</li> <li>**支持并行执行**：相互独立的子任务可以并发处理</li> </ul> <h3>8.1.2 AgentScope Java 的多代理能力</h3></p> <p>AgentScope Java 与 Spring AI Alibaba 深度集成，提供了完整的多代理编排能力：</p> <pre><code class="language-">┌─────────────────────────────────────────────────────────────┐ │ AgentScope Java │ ├─────────────────────────────────────────────────────────────┤ │ 核心抽象层 │ │ ├── ReActAgent 单代理执行引擎 │ │ ├── AgentScopeAgent 代理器（适配 Spring AI Alibaba） │ │ ├── StateGraph 状态图编排 │ │ └── Pipeline Agent 流水线编排（顺序/并行/循环） │ ├─────────────────────────────────────────────────────────────┤ │ 编排模式 │ │ ├── Handoffs 交接模式（控制权转移） │ │ ├── Pipeline 流水线模式（顺序/并行/循环） │ │ ├── Routing 路由模式（条件分发） │ │ ├── Supervisor 监督者模式（层级管理） │ │ ├── SubAgent 子代理模式（动态创建） │ │ └── Workflow 工作流模式（复杂编排） │ └─────────────────────────────────────────────────────────────┘ </code></pre> <h3>8.1.3 核心概念速查</h3> <table border="1" <p>---</p> <h2>8.2 交接（Handoffs）模式</h2> <h3>8.2.1 模式定义</h3> <p>交接（Handoffs）模式是指在一个 Agent 完成当前任务后，将控制权主动转移给另一个 Agent 的架构模式。两个 Agent 之间不再是简单的线性调用，而是根据对话内容动态决定是否交接，以及交接给谁。</p> <p>**核心特征**： <ul><li>Agent 主动决定何时交接（通过调用 handoff 工具）</li> <li>交接后，原 Agent 终止，新 Agent 接管上下文</li> <li>状态图中维护 <code>active_agent</code> 字段作为路由依据</li> <li>支持多轮交接（如：销售 → 支持 → 销售 → 结束）</li> </ul> <h3>8.2.2 架构原理</h3></p> <pre><code class="language-">┌──────────────┐ transfer_to_support ┌──────────────┐ │ Sales Agent │ ──────────────────────────► │ Support Agent│ │ (销售代理) │ 更新 active_agent= │ (技术支持) │ │ │ &quot;support_agent&quot; │ │ └──────────────┘ └──────────────┘ ▲ │ │ transfer_to_sales │ │ ◄─────────────────────────────────────────┘ </code></pre> <p>状态图的条件边根据 <code>active_agent</code> 字段决定下一个节点：</p> <pre><code class="language-java">// 初始路由：默认进入销售代理 graph.addConditionalEdges(START, new RouteInitialAction(), Map.of(SALES_AGENT, SALES_AGENT, SUPPORT_AGENT, SUPPORT_AGENT)); <p>// 销售代理后的路由：交接给支持或结束 graph.addConditionalEdges(SALES_AGENT, new RouteAfterSalesAction(), Map.of(SUPPORT_AGENT, SUPPORT_AGENT, &quot;__end__&quot;, END)); </code></pre></p> <h3>8.2.3 交接工具实现</h3> <p>工作流（Workflow）模式是多代理架构的终极形态，通过有向无环图（DAG）编排任意复杂的业务流程。状态图（StateGraph）是实现工作流的核心抽象，支持： <ul><li>**任意数量的节点**：Agent 节点、功能节点、数据处理节点</li> <li>**条件路由**：根据状态动态决定下一个节点</li>
