<h1>第十章：RAG 检索增强生成</h1> <p>> 本章介绍如何使用 AgentScope Java 构建完整的 RAG（Retrieval-Augmented Generation）系统，包括向量数据库集成、文本分块策略、混合检索以及企业级知识库问答系统的实现。</p> <h2>10.1 RAG 架构与原理</h2> <h3>10.1.1 什么是 RAG</h3> <p>RAG（检索增强生成，Retrieval-Augmented Generation）是一种将信息检索与语言模型生成相结合的技术架构。其核心思想是：在生成回答之前，先从外部知识库中检索与问题相关的内容，然后将这些内容作为上下文提供给语言模型，从而生成更准确、更具事实依据的回答。</p> <h3>10.1.2 RAG 工作流程</h3> <p>RAG 系统的完整工作流程可分为以下几个阶段：</p> <pre><code class="language-">用户问题 → 向量化查询 → 向量相似度检索 → 上下文组装 → LLM 生成回答 </code></pre> <p>**阶段一：文档处理与入库** <pre><code class="language-">原始文档 → 文本分块 → Embedding 向量化 → 向量数据库存储 </code></pre></p> <p>**阶段二：查询与检索** <pre><code class="language-">用户查询 → Embedding 向量化 → 向量数据库检索 → 相关文档排序 </code></pre></p> <p>**阶段三：增强生成** <pre><code class="language-">检索结果 + 用户问题 → 提示词组装 → LLM 生成 → 返回回答 </code></pre></p> <h3>10.1.3 AgentScope Java 中的 RAG 组件</h3> <p>AgentScope Java 提供了完整的 RAG 支持，核心组件包括：</p> <table border="1" cellpadding="8" <ul><li>确保每个块包含完整的语义单元</li> <li>控制块大小以适应模型上下文限制</li> <li>保留检索结果的可读性和信息完整性</li> </ul> <h3>10.3.2 分块策略类型</h3></p> <p>AgentScope Java 通过 <code>SplitStrategy</code> 枚举提供了多种分块策略：</p> <p>**1. 字符分块（CHARACTER）** <ul><li>按固定字符数分割文本</li> <li>简单快速，但可能打断单词或句子</li> <li>适用于对语义完整性要求不高的场景</li> </ul> <pre><code class="language-java">// 按 500 字符分块，无重叠 List&lt;String&gt; chunks = TextChunker.chunkText( text, 500, SplitStrategy.CHARACTER, 0 ); </code></pre></p> <p>**2. 段落分块（PARAGRAPH）** <ul><li>按段落边界分割（双换行符分隔）</li> <li>保留语义完整性，块大小不均匀</li> <li>适用于结构化文档（文章、报告等）</li> </ul> <pre><code class="language-java">// 按段落分块，每个块最多 1000 字符，100 字符重叠 List&lt;String&gt; chunks = TextChunker.chunkText( text, 1000, SplitStrategy.PARAGRAPH, 100 ); </code></pre></p> <p>**3. Token 分块（TOKEN）** <ul><li>按近似 token 数分割（1 token ≈ 4 字符）</li> <li>更好地控制 LLM 上下文使用</li> <li>适用于需要精确控制 token 数量的场景</li> </ul> <pre><code class="language-java">// 按 256 tokens 分块，32 tokens 重叠 List&lt;String&gt; chunks = TextChunker.chunkText( text, 256, SplitStrategy.TOKEN, 32 ); </code></pre></p> <p>**4. 语义分块（SEMANTIC）** <ul><li>按语义边界分割（句子、从句等）</li> <li>当前实现回退到段落分块</li> <li>适用于需要高语义完整性的场景</li> </ul> <h3>10.3.3 分块参数选择指南</h3></p> <p>选择合适的分块参数需要考虑以下因素：</p> <table border="1" cellpadding="8" cellspacing="0"><thead><tr><th>因素</th><th>建议</th></tr></thead><tbody><tr><td>Embedding 模型上下文</td><td>确保块内容在模型上下文限制内</td></tr><tr><td>查询复杂度</td><td>简单问题可用较小块，复杂问题需要较大块</td></tr><tr><td>重叠大小</td><td>较大重叠可避免块边界信息丢失</td></tr><tr><td>检索延迟</td><td>较大块会增加内存和处理开销</td></tr></tbody></table> <p>**推荐配置：**</p> <table border="1" cellpadding="8" cellspacing="0"><thead><tr><th>场景</th><th>chunkSize</th><th>overlapSize</th><th>策略</th></tr></thead><tbody><tr><td>通用问答</td><td>500-1000</td><td>50-100</td><td>PARAGRAPH</td></tr><tr><td>长文档检索</td><td>1000-2000</td><td>100-200</td><td>TOKEN</td></tr><tr><td>短查询精确匹配</td><td>200-500</td><td>0</td><td>CHARACTER</td></tr><tr><td>多模态文档</td><td>500</td><td>50</td><td>PARAGRAPH</td></tr></tbody></table> <h3>10.3.4 分块与文档元数据</h3> <p>分块后，每个块需要关联完整的文档元数据：</p> <pre><code class="language-java">import io.agentscope.core.rag.model.Document; <p>// 执行向量检索 List&lt;Document&gt; vectorResults = store.search(searchDto).block();</p> <p>// 在检索结果上进行关键词过滤 List&lt;Document&gt; filteredResults = vectorResults.stream() .filter(doc -&gt; { String content = doc.getMetadata().getContentText(); return content.contains(keyword) || content.contains(synonym); }) .toList(); </code></pre></p> <h3>10.4.3 RRF 融合算法</h3> <p>当需要融合多个检索来源的结果时，可以使用 RRF（Reciprocal Rank Fusion）算法：</p> <pre><code class="language-java">/** * RRF 融合算法实现 * * @param resultLists 多个检索结果列表 * @param k 融合参数，通常设为 60 * @return 融合后的排序结果 */ public &lt;T&gt; List&lt;T&gt; rrfFusion(List&lt;List&lt;T&gt;&gt; resultLists, int k) { Map&lt;T, Double&gt; scores = new HashMap&lt;&gt;(); <p>// 遍历每个结果列表 for (List&lt;T&gt; results : resultLists) { for (int i = 0; i &lt; results.size(); i++) { T item = results.get(i); // 计算 RRF 分数：1 / (rank + k) double score = 1.0 / (i + k); scores.merge(item, score, Double::sum); } }</p> <p>// 按分数排序 return scores.entrySet().stream() .sorted(Map.Entry.&lt;T, Double&gt;comparingByValue().reversed()) .map(Map.Entry::getKey) .toList(); } </code></pre></p> <h2>10.5 Embedding 模型配置</h2> <h3>10.5.1 Embedding 模型概述</h3> <p>Embedding 模型负责将文本内容转换为高维向量。不同的 Embedding 模型在维度、支持语言、效果等方面有所差异。</p> <h3>10.5.2 阿里云 DashScope Text Embedding</h3> <p>DashScope 是阿里云的模型服务平台，提供文本嵌入模型。</p> <p>**配置示例：**</p> <pre><code class="language-java">import io.agentscope.core.embedding.dashscope.DashScopeTextEmbedding;
