<h1>第九章：代理间通信协议</h1> <p>> 本章讲解 A2A（Agent-to-Agent）协议的原理、AgentScope Java 的实现方式，以及如何通过消息队列实现分布式多代理通信。</p> <p>---</p> <h2>9.1 A2A（Agent-to-Agent）协议详解</h2> <h3>9.1.1 什么是 A2A 协议</h3> <p>A2A（Agent-to-Agent）协议是一种标准化协议，用于**不同 Agent 之间进行通信和协作**。在传统的多代理系统中，每个代理通常需要知道其他代理的实现细节才能进行通信，这导致了紧耦合。 A2A 协议通过定义统一的通信格式和交互模式，实现了代理间的**松耦合通信**。</p> <p>A2A 协议的核心特性： <ul><li>**服务发现**：通过 AgentCard（元数据描述文件）自动发现可用代理</li> <li>**标准化交互**：统一的消息格式和状态机定义</li> <li>**多传输支持**：支持 HTTP/JSON-RPC、WebSocket、消息队列等多种传输方式</li> <li>**技能声明**：代理可以声明自己支持的能力（Skills），方便路由决策</li> </ul> <h3>9.1.2 AgentCard（代理卡片）</h3></p> <p>AgentCard 是 A2A 协议的核心概念，它是一个 JSON 文档，描述了代理的身份、能力、通信方式等元数据。</p> <pre><code class="language-json">{ &quot;name&quot;: &quot;Weather Agent&quot;, &quot;description&quot;: &quot;提供全球天气查询服务&quot;, &quot;version&quot;: &quot;1.0.0&quot;, &quot;provider&quot;: { &quot;organization&quot;: &quot;WeatherService Inc.&quot;, &quot;url&quot;: &quot;https://weather.example.com&quot; }, &quot;url&quot;: &quot;http://localhost:8080&quot;, &quot;capabilities&quot;: { &quot;streaming&quot;: true, &quot;pushNotifications&quot;: true }, &quot;skills&quot;: [ { &quot;id&quot;: &quot;get_weather&quot;, &quot;name&quot;: &quot;获取天气&quot;, &quot;description&quot;: &quot;查询指定城市的当前天气&quot;, &quot;tags&quot;: [&quot;weather&quot;, &quot;forecast&quot;], &quot;examples&quot;: [&quot;北京今天天气怎么样？&quot;, &quot;东京明天会下雨吗？&quot;] } ] } </code></pre> <h3>9.1.3 A2A 消息生命周期</h3> <p>A2A 协议定义了清晰的消息状态机：</p> <pre><code class="language-">Task States: submit -&gt; working -&gt; completed/failed/input-required </code></pre> <p>关键状态说明：</p> <table border="1" cellpadding="8" cellspacing="0"><thead><tr><th>状态</th><th>描述</th></tr></thead><tbody><tr><td><code>submitted</code></td><td>任务已提交，等待处理</td></tr><tr><td><code>working</code></td><td>任务正在处理中</td></tr><tr><td><code>completed</code></td><td>任务成功完成</td></tr><tr><td><code>failed</code></td><td>任务执行失败</td></tr><tr><td><code>input-required</code></td><td>需要用户提供更多信息</td></tr></tbody></table> <p>---</p> <h2>9.2 Agent Protocol 标准</h2> <h3>9.2.1 JSON-RPC 2.0 传输</h3> <p>AgentScope A2A 基于 JSON-RPC 2.0 规范定义了一组标准方法：</p> <table border="1" cellpadding="8" cellspacing="0"><thead><tr><th>方法</th><th>描述</th><th>请求类型</th></tr></thead><tbody><tr><td><code>message/send</code></td><td>发送单条消息，返回完整响应</td><td>同步</td></tr><tr><td><code>message/stream</code></td><td>发送消息，返回流式响应</td><td>流式</td></tr><tr><td><code>tasks/send</code></td><td>发送任务（带状态跟踪）</td><td>同步</td></tr><tr><td><code>tasks/get</code></td><td>获取任务状态和结果</td><td>同步</td></tr><tr><td><code>tasks/cancel</code></td><td>取消正在执行的任务</td><td>同步</td></tr></tbody></table> <h3>9.2.2 核心消息格式</h3> <p>**消息请求示例**：</p> <pre><code class="language-json">{ &quot;method&quot;: &quot;message/stream&quot;, &quot;id&quot;: &quot;a1b2c3d4-e5f6-7890-abcd-ef1234567890&quot;, &quot;jsonrpc&quot;: &quot;2.0&quot;, &quot;params&quot;: { &quot;message&quot;: { &quot;role&quot;: &quot;user&quot;, &quot;kind&quot;: &quot;message&quot;, &quot;contextId&quot;: &quot;session-001&quot;, &quot;metadata&quot;: { &quot;userId&quot;: &quot;user-001&quot;, &quot;sessionId&quot;: &quot;session-001&quot; }, &quot;parts&quot;: [ { &quot;kind&quot;: &quot;text&quot;, &quot;text&quot;: &quot;请帮我查询北京的天气&quot; } ], &quot;messageId&quot;: &quot;msg-001&quot; } } } </code></pre> <p>**消息响应示例**：</p> <pre><code class="language-json">{ &quot;id&quot;: &quot;a1b2c3d4-e5f6-7890-abcd-ef1234567890&quot;, &quot;jsonrpc&quot;: &quot;2.0&quot;, &quot;result&quot;: { &quot;status&quot;: &quot;completed&quot;, &quot;message&quot;: { &quot;role&quot;: &quot;assistant&quot;, &quot;kind&quot;: &quot;message&quot;, &quot;parts&quot;: [ { &quot;kind&quot;: &quot;text&quot;, &quot;text&quot;: &quot;北京今天天气晴朗，气温 15-25°C，适合外出。&quot; } ] } } } </code></pre> <h3>9.2.3 事件推送（Server-Sent Events）</h3> <p>A2A 协议支持通过 SSE（Server-Sent Events）进行流式响应和事件推送：</p> <pre><code class="language-">event: task data: {&quot;taskId&quot;:&quot;task-001&quot;,&quot;status&quot;:&quot;working&quot;,&quot;message&quot;:{...}} <p>event: task data: {&quot;taskId&quot;:&quot;task-001&quot;,&quot;status&quot;:&quot;working&quot;,&quot;message&quot;:{...}}</p> <p>event: task data: {&quot;taskId&quot;:&quot;task-001&quot;,&quot;status&quot;:&quot;completed&quot;,&quot;message&quot;:{...}} </code></pre></p> <p>---</p> <h2>9.3 消息队列集成（RocketMQ）</h2> <h3>9.3.1 为什么需要消息队列</h3> <p>在分布式多代理系统中，HTTP 同步调用存在以下局限性：</p> <p>1. **紧耦合**：调用方需要知道被调用方的网络地址 2. **同步阻塞**：调用方需要等待响应才能继续 3. **单点故障**：被调用方不可用时整个流程中断 4. **扩展性差**：难以支持高并发场景</p> <p>消息队列通过**异步解耦**解决了这些问题： <ul><li>**发布/订阅模式**：代理之间不需要直接通信</li> <li>**削峰填谷**：应对突发流量</li> <li>**可靠性保证**：消息持久化、重试机制</li> <li>**地理分布**：支持跨机房、跨地域通信</li> </ul> <h3>9.3.2 RocketMQ 集成架构</h3></p> <p>AgentScope Java 通过 RocketMQ 实现了 A2A 协议的异步传输：</p> <pre><code class="language-">┌─────────────┐ ┌──────────────┐ ┌─────────────┐ │ Client │──────▶│ RocketMQ │──────▶│ Server │ │ (Publisher)│ │ Broker │ │ (Consumer) │ └─────────────┘ └──────────────┘ └─────────────┘ ▲ │ LiteTopic (响应通道) │ ┌────┴─────┐ │ Response │ │ Topic │ └──────────┘ </code></pre> <p>关键概念： <ul><li>**BizTopic**：业务消息主题，传输 Agent 间的主消息</li> <li>**LiteTopic**：轻量级主题，用于接收定向响应</li> <li>**ConsumerGroup**：消费者组，实现负载均衡和故障转移</li> </ul> <h3>9.3.3 消息格式设计</h3></p> <p>RocketMQ 传输使用的消息扩展格式：</p> <pre><code class="language-json">{ &quot;messageId&quot;: &quot;msg-uuid-001&quot;, &quot;sessionId&quot;: &quot;session-001&quot;, &quot;sourceAgent&quot;: &quot;agent-client-001&quot;, &quot;targetAgent&quot;: &quot;agent-server-001&quot;, &quot;transportType&quot;: &quot;rocketmq&quot;, &quot;payload&quot;: { &quot;message&quot;: {...}, &quot;metadata&quot;: {...} }, &quot;timestamp&quot;: 1704067200000 } </code></pre> <p>---</p>
