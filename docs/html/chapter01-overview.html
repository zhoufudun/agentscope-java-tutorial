<h1>第一章：AgentScope Java 概述</h1> <h2>1.1 什么是 AgentScope Java</h2> <p>AgentScope Java 是一个面向智能体的编程框架，用于构建基于大语言模型（LLM）的应用。它脱胎于 Python 版 AgentScope，并针对 Java 生态进行了深度优化。与传统的硬编码工作流不同，AgentScope Java 强调**智能体（Agent）**的核心地位——由 LLM 驱动、自主演知、自适应执行。</p> <p>**核心定位**：用 Java 构建生产级 AI 智能体，让企业级 Java 项目能够无缝集成 LLM 驱动的智能体能力。</p> <p>**典型应用场景**： <ul><li>**自动化助手**：邮件处理、文档生成、数据分析</li> <li>**智能客服**：多轮对话、意图识别、工具调用</li> <li>**代码助手**：代码审查、Bug 修复、代码生成</li> <li>**多智能体协作**：复杂任务分解与多角色协同</li> </ul> **与 Python 版的核心差异**：</p> <table border="1" cellpadding="8" cellspacing="0"><thead><tr><th>特性</th><th>AgentScope Python</th><th>AgentScope Java</th></tr></thead><tbody><tr><td>启动性能</td><td>解释执行，较慢</td><td>编译执行，毫秒级冷启动</td></tr><tr><td>生态集成</td><td>科学计算生态</td><td>Spring Boot、企业级中间件</td></tr><tr><td>部署方式</td><td>Python 环境依赖</td><td>纯 JVM，原生镜像编译</td></tr><tr><td>线程模型</td><td>asyncio 单线程</td><td>Project Reactor 响应式非阻塞</td></tr></tbody></table> <h2>1.2 核心概念：ReAct 推理-行动范式</h2> <h3>1.2.1 ReAct 是什么</h3> <p>ReAct（Reasoning and Acting）是一种让大语言模型在执行任务时**交替进行推理（Reasoning）和行动（Acting）**的设计范式。其核心思想是：模型不仅生成最终答案，而是先"思考"，然后根据思考结果决定是否调用外部工具，最后综合工具返回的信息继续迭代，直到完成任务。</p> <p>这一思想最早由论文 *ReAct: Synergizing Reasoning and Acting in Language Models*（Yao et al., 2022）提出。相比于直接让模型生成答案，ReAct 有几个关键优势： <ul><li>**可解释性**：每一步推理都显式可见，便于追踪决策过程</li> <li>**可控性**：工具调用受框架约束，不会无限循环或执行危险操作</li> <li>**准确性**：通过外部工具获取实时、精确的信息，避免模型幻觉</li> </ul> <h3>1.2.2 ReAct 执行流程</h3></p> <p>AgentScope Java 中，ReAct 智能体的执行遵循以下循环：</p> <pre><code class="language-">┌──────────────────────────────────────────────────────┐ │ 开始执行 │ └─────────────────────┬────────────────────────────────┘ ▼ ┌──────────────────────────────────────────────────────┐ │ 阶段一：推理（Reasoning） │ │ - 模型分析当前状态、用户输入、工具结果 │ │ - 决定下一步行动（回答 or 调用工具） │ └─────────────────────┬────────────────────────────────┘ ▼ ┌───────────────┐ │ 是否调用工具？ │──否──► 返回最终回复 ◄──┐ └───────┬───────┘ │ │ 是 │ ▼ │ ┌──────────────────────────────────────────────────────┐ │ 阶段二：行动（Acting） │ │ - 根据推理结果选择并调用对应工具 │ │ - 收集工具返回结果 │ └─────────────────────┬────────────────────────────────┘ │ │ ▼ │ ┌───────────────┐ │ │ 是否达到最大 │──是──► 返回当前结果 │ │ │ 迭代次数？ │ │ │ └───────┬───────┘ │ │ │ 否（继续循环） │ │ └──────────────────────────────────┘ </code></pre> <p>在 AgentScope Java 中，这三个阶段通过事件钩子（Hook）暴露： <ul><li><code>PreReasoningEvent</code> / <code>PostReasoningEvent</code>：推理前后插入自定义逻辑</li> <li><code>PreActingEvent</code> / <code>PostActingEvent</code>：工具调用前后监控执行</li> <li><code>PreSummaryEvent</code> / <code>PostSummaryEvent</code>：生成最终回复前调整内容</li> </ul> <h3>1.2.3 消息与会话</h3></p> <p>AgentScope Java 使用 <code>Msg</code> 对象作为所有通信的基本单元。每个消息包含： <ul><li>**角色（Role）**：<code>USER</code>（用户）、<code>ASSISTANT</code>（助手）、<code>SYSTEM</code>（系统）、<code>TOOL</code>（工具）</li> <li>**内容块（Content Blocks）**：支持文本、图片、音频、视频、思维链、工具调用等多种类型</li> <li>**元数据（Metadata）**：时间戳、生成原因等附加信息</li> </ul> 会话（Session）管理多个消息的上下文，自动维护对话历史，支持多轮交互。</p> <h3>1.2.4 工具与工具箱</h3> <p>工具（Tool）是智能体与外部世界交互的桥梁。AgentScope Java 的工具系统基于方法级注解，任意带有 <code>@Tool</code> 注解的公共方法都会自动注册为可用工具。多个工具组织为工具箱（Toolkit），方便批量管理和隔离。</p> <pre><code class="language-java">// 工具示例 @Tool(name = &quot;get_weather&quot;, description = &quot;查询城市天气&quot;) public String queryWeather(@ToolParam(name = &quot;city&quot;) String city) { // 调用天气 API return &quot;晴，25°C&quot;; } </code></pre> <h2>1.3 项目架构与模块划分</h2> <p>AgentScope Java 采用多模块 Maven 项目结构，主 pom 文件定义了以下模块：</p> <pre><code class="language-">agentscope-parent/ ├── agentscope-core/ # 核心框架 ├── agentscope-harness/ # 安全沙箱执行环境 ├── agentscope-extensions/ # 扩展功能（Pipeline、RAG 等） ├── agentscope-examples/ # 示例代码 ├── agentscope-dependencies-bom/ # 统一依赖版本管理 └── agentscope-distribution/ # 发布包 </code></pre> <h3>1.3.1 agentscope-core（核心框架）</h3> <p>这是框架的主体，包含了构建智能体应用所需的全部核心接口和实现：</p> agentscope-harness（安全沙箱）</h3> <p>Harness 为不可信的第三方工具代码提供隔离执行环境，防止恶意代码访问系统资源。主要特性： <ul><li>**文件系统隔离**：工具只能访问指定工作目录，无法读写系统敏感路径</li> <li>**GUI 自动化沙箱**：内置 GUI 操作的安全预置环境</li> <li>**资源限制**：CPU、内存、执行时间均有上限</li> </ul> <h3>1.3.3 agentscope-extensions（扩展功能）</h3></p> <p>包含非核心但常用的扩展能力： <ul><li>**A2A（Agent-to-Agent）协议**：多智能体之间通过标准协议通信</li> <li>**MCP（Model Context Protocol）**：集成 MCP 兼容的外部工具和服务</li> <li>**Pipeline**：多代理流水线编排</li> </ul> <h3>1.3.4 agentscope-dependencies-bom（依赖管理）</h3></p> <p>统一的 Maven BOM（Bill of Materials），管理所有第三方依赖的版本，避免版本冲突。</p> <h2>1.4 环境准备</h2> <h3>1.4.1
