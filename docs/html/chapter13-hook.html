<h1>第十三章：Hook 钩子系统</h1> <p>AgentScope Java 的 Hook 钩子系统是实现 Agent 运行时可观测性、可干预性和业务扩展的核心机制。通过 Hook，开发者可以在 Agent 执行的关键阶段插入自定义逻辑，实现日志记录、性能监控、安全检查、人工介入等功能，而无需修改核心 Agent 代码。</p> <h2>13.1 生命周期钩子概念</h2> <h3>13.1.1 什么是 Hook</h3> <p>Hook（钩子）是一种事件监听机制。AgentScope Java 将 Agent 的执行过程拆解为一系列生命周期事件，每个事件触发时，所有注册的 Hook 都会被调用。Hook 可以读取事件上下文、修改事件数据、甚至中止 Agent 的执行流程。</p> <p>**核心设计原则：** <ul><li>**统一事件模型**：所有 Hook 事件都通过 <code>onEvent(T event)</code> 方法处理，使用 Java 17+ 的 pattern matching 进行类型分发</li> <li>**响应式编程**：Hook 返回 <code>Mono<T></code>（Project Reactor），支持异步处理和链式调用</li> <li>**优先级机制**：Hook 可设置优先级（0-1000），数值越小优先级越高，优先执行</li> <li>**可修改事件**：部分事件（如 <code>PreReasoningEvent</code>、<code>PostActingEvent</code>）提供了 setter 方法，允许 Hook 修改后续处理的数据</li> </ul> <h3>13.1.2 事件类型体系</h3></p> <p>AgentScope Java 定义了完整的生命周期事件类型，存放在 <code>io.agentscope.core.hook</code> 包中：</p> <pre><code class="language-">HookEvent (sealed abstract class) ├── PreCallEvent - Agent 调用开始前（可修改输入） ├── PostCallEvent - Agent 调用完成后（可修改最终输出） ├── ReasoningEvent (sealed) │ ├── PreReasoningEvent - LLM 推理前（可修改输入消息） │ ├── PostReasoningEvent - LLM 推理后（可修改推理结果，可中止） │ └── ReasoningChunkEvent - 推理流式输出（只读） ├── ActingEvent (sealed) │ ├── PreActingEvent - 工具执行前（可修改工具参数） │ ├── PostActingEvent - 工具执行后（可修改结果，可中止） │ └── ActingChunkEvent - 工具流式输出（只读） ├── SummaryEvent (sealed) │ ├── PreSummaryEvent - 摘要生成前 │ ├── SummaryChunkEvent - 摘要流式输出 │ └── PostSummaryEvent - 摘要生成后 └── ErrorEvent - 执行出错（只读） </code></pre> <h3>13.1.3 事件流向图</h3> <pre><code class="language-">┌─────────────────────────────────────────────────────────────────┐ │ Agent.call() │ ├─────────────────────────────────────────────────────────────────┤ │ 1. PreCallEvent ──► [Hook] ──► Hook ──► ... │ │ ↓ │ │ 2. PreReasoningEvent ──► [Hook] ──► Hook ──► ... │ │ ↓ │ │ 3. LLM.stream() ──► ReasoningChunkEvent ──► ... │ │ ↓ │ │ 4. PostReasoningEvent ──► [Hook] ──► Hook ──► ... │ │ ↓ │ │ ┌─────────────────────────────────────────┐ │ │ │ 循环：ToolUseBlock 存在？ │ │ │ │ ├─► PreActingEvent ──► [Hook] │ │ │ │ │ ↓ │ │ │ │ │ Tool.execute() ──► ActingChunk │ │ │ │ │ ↓ │ │ │ │ └─► PostActingEvent ──► [Hook] │ │ │ │ ↓ │ │ │ └─────► 回到 PreReasoningEvent │ │ │ ↓ │ │ 5. PreSummaryEvent ──► [Hook] │ │ ↓ │ │ 6. SummaryChunkEvent ──► ... │ │ ↓ │ │ 7. PostSummaryEvent ──► ... │ │ ↓ │ │ 8. PostCallEvent ──► [Hook] ──► 返回最终消息 │ └─────────────────────────────────────────────────────────────────┘ ↓ ErrorEvent （任意阶段出错时触发） </code></pre> <h3>13.1.4 Hook 接口详解</h3> <pre><code class="language-java">public interface Hook { <p>/** * 处理钩子事件 * * @param event 钩子事件 * @param &lt;T&gt; 事件具体类型 * @return 包含潜在修改后事件的无状态 Mono */ &lt;T extends HookEvent&gt; Mono&lt;T&gt; onEvent(T event);</p> <p>/** * 可选：随 Hook 一起安装的工具列表 * 在 Agent 构建时，这些工具会自动注册到 Agent 的 Toolkit 中 * * @return 工具实例列表（默认返回空列表） */ default List&lt;Object&gt; tools() { return Collections.emptyList(); }</p> <p>/** * 钩子优先级（数值越小越先执行） * * 常见优先级范围： * - 0-50: 系统关键钩子（认证、安全） * - 51-100: 高优先级钩子（验证、预处理） * - 101-500: 普通业务钩子 * - 501-1000: 低优先级钩子（日志、监控） * * @return 优先级数值（默认 100） */ default int priority() { return 100; } } </code></pre></p> <h3>13.1.5 事件可修改性</h3> <table border="1" cellpadding="8" cellspacing="0"><thead><tr><th>事件类型</th><th>可修改</th><th>允许的操作</th></tr></thead><tbody><tr><td>PreCallEvent</td><td>是</td><td><code>setInputMessages(List<Msg>)</code></td></tr><tr><td>PreReasoningEvent</td><td>是</td><td><code>setInputMessages(List<Msg>)</code>, <code>setGenerateOptions(GenerateOptions)</code></td></tr><tr><td>PostReasoningEvent</td><td>是</td><td><code>setReasoningMessage(Msg)</code>, <code>stopAgent()</code>, <code>gotoReasoning()</code></td></tr><tr><td>PreActingEvent</td><td>是</td><td>工具参数修改（通过修改 ToolUseBlock）</td></tr><tr><td>PostActingEvent</td><td>是</td><td><code>setToolResult(ToolResultBlock)</code>, <code>stopAgent()</code></td></tr><tr><td>PostCallEvent</td><td>是</td><td><code>setFinalMessage(Msg)</code></td></tr><tr><td>ReasoningChunkEvent</td><td>否</td><td>只读，流式通知</td></tr><tr><td>ActingChunkEvent</td><td>否</td><td>只读，流式通知</td></tr><tr><td>ErrorEvent</td><td>否</td><td>只读，错误通知</td></tr></tbody></table> <h2>13.2 内置钩子实现</h2> <p>AgentScope Java 提供了一系列开箱即用的内置 Hook，满足常见的监控、日志、追踪需求。</p> <h3>13.2.1 JsonlTraceExporter - JSONL 追踪导出器</h3> <p>**位置**：<code>io.agentscope.core.hook.recorder.JsonlTraceExporter</code></p> <p>**功能**：将所有 Hook 事件以 JSON Lines 格式写入文件，适用于本地调试、离线排查和 GitHub Issue 附图。</p> <p>**特性**： <ul><li>异步写入，单线程队列保证顺序一致性</li> <li>支持 OpenTelemetry trace_id 和 span_id 注入</li> <li>可配置的事件过滤（默认记录主要事件）</li> <li>best-effort 模式：IO 错误不中断 Agent 执行</li> </ul> **使用示例**：</p> <pre><code class="language-java">// 创建追踪导出器 JsonlTraceExporter tracer = JsonlTraceExporter.builder( Path.of(&quot;logs&quot;, &quot;agent-trace.jsonl&quot;)) .includeReasoningChunks(true) // 包含推理流式输出 .includeActingChunks(true) // 包含工具执行流式输出 .includeSummary(true) // 包含摘要事件 .priority(900) // 低优先级（日志类钩子） .build(); import io.agentscope.core.message.Msg; import io.agentscope.core.message.ToolResultBlock; import io.agentscope.core.message.ToolUseBlock; import org.slf4j.Logger; import org.slf4j.LoggerFactory; import reactor.core.publisher.Mono;</p> <p>import java.util.List;</p> <p>/** * 生产级日志钩子：记录所有关键生命周期事件 * 使用 SLF4J/Logback 与 Spring Boot 集成 */ public class LoggingHook implements Hook {</p> <p>private static final Logger log = LoggerFactory.getLogger(LoggingHook.class);</p> <p>// 可配置：是否记录流式 chunks（可能产生大量日志） private final boolean logStreamingChunks;</p> <p>public LoggingHook() { this(false); case PostReasoningEvent e -&gt; handlePostReasoning(e); case ReasoningChunkEvent e when logStreamingChunks -&gt; handleReasoningChunk(e); case PreActingEvent e -&gt; handlePreActing(e); case PostActingEvent e -&gt; Mono&lt;T&gt; handlePostCall(PostCallEvent e) { Msg finalMsg = e.getFinalMessage(); log.info(&quot;[{}] Agent 调用完成 - 响应内容长度: {}&quot;, e.getAgent().getName(), finalMsg != null ? finalMsg.getTextContent().length() : 0); return Mono.just((T) event); }</p> <p>private &lt;T extends HookEvent&gt; Mono&lt;T&gt; handlePreReasoning(PreReasoningEvent e) { log.debug(&quot;[{}] 准备推理 - 模型: {}, 输入消息数: {}&quot;, e.getAgent().getName(), e.getModelName(), e.getInputMessages().size()); return Mono.just((T) event); }</p> <p>private &lt;T extends HookEvent&gt; Mono&lt;T&gt; handlePostReasoning(PostReasoningEvent e) { Msg reasoningMsg = e.getReasoningMessage(); if (reasoningMsg != null) { List&lt;ToolUseBlock&gt; toolCalls = reasoningMsg.getContentBlocks(ToolUseBlock.class); log.info(&quot;[{}] 推理完成 - ToolCalls: {}&quot;, e.getAgent().getName(), toolCalls.size()); } else { log.info(&quot;[{}] 推理完成 - 无 ToolCall&quot;, e.getAgent().getName()); } return Mono.just((T) event); }</p> <p>private &lt;T extends HookEvent&gt; Mono&lt;T&gt; handleReasoningChunk(ReasoningChunkEvent e) { Msg chunk = e.getIncrementalChunk(); String text = chunk != null ? chunk.getTextContent() : &quot;&quot;; log.trace(&quot;[{}] 推理 Chunk: {}&quot;, e.getAgent().getName(), text.length() &gt; 100 ? text.substring(0, 100) + &quot;...&quot; : text); return Mono.just((T) event); }</p> <p>private &lt;T extends HookEvent&gt; Mono&lt;T&gt; handlePreActing(PreActingEvent e) { ToolUseBlock toolUse = e.getToolUse(); log.info(&quot;[{}] 执行工具: {} - 输入: {}&quot;, e.getAgent().getName(), toolUse.getName(), toolUse.getInput()); return Mono.just((T) event); }</p> <p>private &lt;T extends HookEvent&gt; Mono&lt;T&gt; handlePostActing(PostActingEvent e) { ToolResultBlock result = e.getToolResult(); String output = result != null &amp;&amp; !result.getOutput().isEmpty() ? result.getOutput().get(0).toString() : &quot;(empty)&quot;; log.info(&quot;[{}] 工具执行完成: {} - 结果: {}&quot;, e.getAgent().getName(), e.getToolUse().getName(), output.length() &gt; 200 ? output.substring(0, 200) + &quot;...&quot; : output); return Mono.just((T) event); }</p> <p>private &lt;T extends HookEvent&gt; Mono&lt;T&gt; handleActingChunk(ActingChunkEvent e) { ToolResultBlock chunk = e.getChunk(); log.trace(&quot;[{}] 工具 Chunk: {}&quot;, e.getAgent().getName(), e.getToolUse().getName()); return Mono.just((T) event); }</p> <p>private &lt;T extends HookEvent&gt; Mono&lt;T&gt; handleError(ErrorEvent e) { log.error(&quot;[{}] 执行出错: {} - {}&quot;, e.getAgent().getName(), e.getError().getClass().getSimpleName(), e.getError().getMessage(), e.getError()); return Mono.just((T) event); } } </code></pre></p> <h3>13.2.3 其他内置 Hook 示例</h3> <table border="1" cellpadding="8" cellspacing="0"><thead><tr><th>Hook 类</th><th>位置</th><th>功能</th></tr></thead><tbody><tr><td>TTSHook</td><td><code>io.agentscope.core.hook.TTSHook</code></td><td>文本转语音流式输出</td></tr><tr><td>SkillHook</td><td><code>io.agentscope.core.skill.SkillHook</code></td><td>技能动态注册</td></tr><tr><td>GenericRAGHook</td><td><code>io.agentscope.core.rag.GenericRAGHook</code></td><td>RAG 检索增强</td></tr><tr><td>AutoContextHook</td><td><code>agentscope-extensions-autocontext-memory</code></td><td>自动上下文记忆</td></tr><tr><td>StudioMessageHook</td><td><code>agentscope-extensions-studio</code></td><td>Studio 消息同步</td></tr></tbody></table> <h2>13.3 自定义钩子开发</h2> <h3>13.3.1 基本开发模式</h3> <p>自定义 Hook 需要实现 <code>Hook</code> 接口，核心是重写 <code>onEvent</code> 方法。使用 Java 17+ 的 pattern matching 进行事件类型匹配：</p> <pre><code class="language-java">public class MyCustomHook implements Hook { <p>@Override public &lt;T extends HookEvent&gt; **事件类型体系清晰** <ul><li><code>HookEvent</code> 是所有事件的基类，采用 sealed class 设计</li> <li>12 种事件类型覆盖推理、工具执行、摘要、错误等场景</li> <li>部分事件可修改（带 setter），部分仅通知（只读）</li> </ul> 3. **优先级决定执行顺序** <ul><li>数值越小优先级越高，范围 0-1000</li> <li>建议分层设计：系统关键(0-50) → 业务逻辑(51-500) → 监控日志(501-1000)</li> </ul> 4. **内置 Hook 开箱即用** <ul><li><code>JsonlTraceExporter</code> 提供完整的调用追踪</li> <li>复杂场景可组合多个内置 Hook</li> </ul> 5. **自定义 Hook
